The problem

A squad is three people and four tools that do not know about each other.

Nothing here is a tooling gap in the abstract. This is where the work actually goes missing.

01

The group chat

Where the good idea was posted at 01:40 and scrolled past by morning. No structure, no history you can search, no way to say who owns it.

02

The shared doc

The proposal, the notebook, the template library. Version three lives in someone's Downloads folder, and nobody is sure which one is printed.

03

The board nobody opens

Set up with great intentions in week one. Abandoned by week three because finishing a card gave you nothing back.

Campus telemetry

Everyone on campus sits somewhere on the same ladder.

Connect a judge and Squadron reads your rating, then plots the whole cohort on one scale. A squad can see the range it has — and the range it is missing — before it commits to three people for a season.

The workspace

Channels, board and notebook — scoped to the squad, not to you.

Switch squads from the panel at the top and everything changes with it: the channels, the sprint, the standings, the notebook. One workspace per team, not one workspace per person.

Greedy pitfalls we have actually lost points to

Page 14 of 21 · meera_ct edited 2 hours ago · branch notebook/v3

Every entry here cost us a real penalty. Keep it to one page — if it needs two, it belongs in the long notes, not the printed notebook.

The ICPC notebook is capped at 25 printed pages and is the only reference allowed on the table. Everything here has to be readable at arm's length under contest lighting.

1. Ties are not free

When two candidates have equal cost, the comparator must still be a strict weak ordering. Sorting on cost alone leaves the order implementation-defined, so the same submission can pass locally and fail on the judge. Break every tie on the original index.

2. Exchange argument before you commit

If you cannot state the swap that proves the greedy choice is safe, you are guessing. On problem D of the 2023 regional we guessed, and it cost 68 minutes of penalty plus the two wrong submissions.

notebook/greedy/schedule.cpp · page 14
// Weighted job scheduling — sort by deadline, then drop the
// heaviest-cost job when the heap overflows the slot budget.
long long schedule(vector<Job> jobs) {
    sort(jobs.begin(), jobs.end(), [](const Job& a, const Job& b){
        return a.deadline != b.deadline ? a.deadline < b.deadline : a.idx < b.idx;
    });
    priority_queue<long long, vector<long long>, greater<>> kept;
    long long total = 0;
    for (const Job& j : jobs) {
        kept.push(j.profit); total += j.profit;
        if ((int)kept.size() > j.deadline) { total -= kept.top(); kept.pop(); }
    }
    return total;
}
